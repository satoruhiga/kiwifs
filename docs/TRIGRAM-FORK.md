# trigram 検索フォークの運用

対象は `v0.19.84` ベースの `local/trigram-search`。FTS5 の tokenizer を単一の `trigram` に変更する。本文は引き続きディスク上のファイルを正本とし、検索 DB には保存しない。

## 検索仕様

- 日本語の文中部分文字列を検索できる（例：`利用者の関心モデルを更新する。` → `関心モデル`）。
- 検索語は Unicode 文字で 3 文字以上が必要。1〜2 文字の語は非対応。短い語のための別インデックスやフォールバックは設けない。
- 通常の空白区切り検索は従来どおり AND。英語も部分文字列・大文字小文字を区別しない検索になり、Porter 語幹処理とアクセント除去は行わない。明示的な FTS5 構文の扱いは変更しない。
- `contentless_delete=1` と置換 INSERT により、更新前の本文の検索語を残さない。削除の可視性は従来どおり `doc_paths` で制御する。

## 既存 DB の移行

1. 同じ KB を使うサーバー・CLI とファイル更新を停止し、KB と `.kiwi/state/` をバックアップする。ディスクの空き容量も確保する。
2. このフォークのバイナリで対象 KB を開く。初回オープン時に既存の `docs` 定義を確認し、旧 Porter テーブル（contentless 以前の形式も含む）を自動移行する。手動で DB を削除する必要はない。
3. 移行は `docs` と `doc_paths` だけを単一トランザクション内で再作成・再投入する。`.md` / `.mdx` は Storage から読み、メタデータ、リンク、閲覧履歴、設定用テーブル、ビューは削除しない。読み取り・走査・SQL のエラーではロールバックし、オープンをエラーで返す。原因を解消して再実行する。
4. `関心モデル` など実際の本文に含まれる語で検索を確認する。移行のための `kiwifs reindex` は不要。明示的な reindex は従来どおり派生メタデータ等も再生成するため、FTS だけの移行とは区別する。

移行済みで空でないインデックスは再オープン時に再構築しない。空の既存インデックスは FTS とパスだけを再投入し、メタデータを消さない。移行中は全文を読み直すため、初回起動に時間がかかり、WAL と旧インデックスを含む一時的な容量が必要になる。旧版に戻す場合は停止後にバックアップした state を復元するか、旧版の reindex で派生インデックスを作り直す。

## 検証と容量

`GOTOOLCHAIN=auto go test ./internal/search/... -count=1` で検証する。API・pipeline・CLI のテストも対象。Go 1.27 が必要。

位置情報を持つ trigram は単語インデックスより大きい。既存の 1,000 文書テストでは本文 2.46 MB に対して DB は約 20.40 MB（約 8.3 倍）。このフォークでは当該テストの容量上限を Porter 用の 2 倍から trigram 用の 10 倍へ明示的に変更した。実 KB の容量・起動時間を保証する数値ではないため、配備前にコピーで計測する。
